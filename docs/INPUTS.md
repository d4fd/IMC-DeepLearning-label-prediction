# External inputs and optional execution

**None of the files described below is included.** Filenames/field names are
schemas, not examples of study records. Only use inputs you are authorized to
access. A clean clone supports the synthetic demo, not real-study reproduction.

## Runtime locations

`workflow/submission_paths.py` resolves these environment variables:

| Variable | Meaning | Default |
|---|---|---|
| `PROJECT_WORK_DIR` | Generated contracts, reports, checkpoints and staging area | `runs/workflow/` below the repository, ignored |
| `PROJECT_SOURCE_DIR` | External `metadata.csv` and `panel.csv` | `input/` below the work directory |
| `PROJECT_IMAGES_DIR` | External `<sample_id>.tiff` images | `IMC_images/` below the source directory |
| `PROJECT_DATASET_DIR` | Generated Spora-format dataset | `datasets/rcc2025necrosis/` below the work directory |
| `PROJECT_TOKEN_DIR` | Generated train/validation tile-token cache | `tile_tokens/` below the work directory |
| `PROJECT_PID_SALT` | Locally generated secret for private patient pseudonyms | None; required for dataset preparation |
| `PROJECT_AUX_PROVENANCE_CONFIRMED` | Set to `1` only after verifying independent, pre-fitting auxiliary annotations | Not confirmed |
| `PROJECT_DEMO_TISSUE_ID` | Identifier for your separately obtained, authorized upstream demo tissue | None |

Prefer an external work directory. Do not put real inputs under tracked source,
documentation or tests. Never commit a salt, raw/pseudonymous patient map or any
generated artifact. Keep the salt stable privately if continuing a runtime split.
The split changes if the secret changes.

## Source contracts

- **Images:** channels-first or loader-compatible TIFFs aligned with the panel.
  The dataset builder retains its original `(46, 224, 224)` shape contract.
- **Panel:** `channel`, `clean_target` fields in source-channel order.
- **Reviewed marker manifest:** `phase1_marker_manifest.csv` in the work
  directory. Fields used across scripts include `source_channel`, `original_name`,
  `hugo_name`, `uniprot_id`, `disposition`, `nuclear_marker`, `notes`, `qc_pass` and
  `source_index`. The marker stage requires the exact ordered columns shown in
  its schema check. Review each biological identity; do not infer mappings
  from unknown channel names. Check the precise fields used by each stage before
  preparing a manifest for a different panel.
- **Marker equivalence references:** separately generate pinned-tool embeddings
  under `marker_embeddings/pinned_tool_reference/` in the work directory. The
  contact-free marker runner requires nonempty references to check its reduction;
  it does not silently skip equivalence validation in a clean clone.
- **Annotations:** `sample_id`, `PID`, `necrose`, and `TMA`, plus auxiliary schema
  fields `gender`, `age`, `subtype_combined`, `lymphocytes_combined`, `pT_combined`,
  `ISUP_combined`, `PDL1_score`, `genomic_subtype`, `genomic_risk` and
  `metabolic_subtype`. Missing auxiliary labels are permitted. The contract
  generator documents semantic vocabularies and training-patient eligibility.
  These fields are targets/audit keys, not encoder or inference inputs.
- **Prepared dataset:** `metadata/tissues.parquet`, IMC channel tables,
  standardization tables, tile coordinates and OME-Zarr arrays in the layout
  produced by the dataset builder. `patient_id` assigns each patient to exactly
  one split. The same patient must never cross partitions.
- **Development cache:** one `<tissue_id>.npz` per core below `train/` or
  `validation/`, containing either `tokens` shaped `(n_tiles, 256, 512)` or
  float32 `tile_features` shaped `(n_tiles, 512)`, plus `coords` shaped
  `(n_tiles, 2)`. Extraction/verification expects full tokens; the head loader
  additionally accepts compact per-tile means. Generated provenance manifests
  bind caches to the current split, preprocessing, markers and upstream weights.
- **Evaluation cache:** separately authorized encoder outputs below
  `outputs/phase6/test_features/` in the work directory: each core's NPZ has
  finite `features` shaped `(n_tiles, 512)` computed using the same locked
  preprocessing and frozen encoder as development. `phase6_extract_test_features.py`
  generates these private runtime caches only after explicit test authorization
  and a completed final lock. Its `provenance.json` binds exact feature hashes
  to that lock; the evaluator verifies it before inference. Install all encoder
  assets before locking. Do not extract or inspect test features during development.
- **Heads/contracts:** generated by the scientific stages, never supplied by
  this repository. The evaluator reads the eight `head08_seed*.pt` files in
  `final_model_08/` and computes a new threshold from authorized validation data.

The sources show the original stage-to-stage file contracts. They are not a
general-purpose dataset adapter, nor a complete new-data ingestion service.

## Optional full environment

The demo does not need VirTues, Spora, images, weights or a GPU. Encoder stages
need a compatible Linux/CUDA environment and separate upstream installations:

```bash
python -m pip install -r requirements-encoder.txt
```

Obtain VirTues and Spora from the links/revisions in
`THIRD_PARTY_NOTICES.md`, inspect their install instructions/licenses, and install
them into your environment. Put the VirTues checkout at `virtues/` below your
work directory, and its separately licensed weight file at
`checkpoints/virtues-sp32/model.safetensors`. Marker assets are generated into
the work directory. Requirements are not an exact historical lock, and the full
external environment has not been recreated or tested for this publication.

The retained encoder entry points are the project's T4-adapted path. They require
the eval-only adapter before importing model modules. Do not run upstream setup
unchanged on T4: FlashAttention-2 does not support that GPU. Other hardware needs
its own reviewed attention setup; merely installing dependencies is insufficient.

## Explicit execution

```bash
python workflow/run_stage.py list
python workflow/run_stage.py prepare --check
```

Preflight checks only basic file/dependency presence, not input validity, licenses
or scientific compatibility. Once external inputs and the protocol are reviewed,
`--execute` runs a selected stage. Additional flags after `--` go to that script:

```bash
python workflow/run_stage.py search --execute -- --execute
python workflow/run_stage.py evaluate --execute -- --lock
python workflow/run_stage.py extract-test --execute -- --allow-test-access
python workflow/run_stage.py evaluate --execute -- --evaluate --allow-test-access
```

The repeated `--execute` in the search example is intentional: both the safety
launcher and the underlying search require opt-in. **Do not run these examples
just to inspect the repository.** Real training/occlusion can be expensive;
evaluation must follow a completed model/threshold lock and authorized test use.
Use a new private work directory for independent runs, not the original study's
artifacts. Never treat a rerun on an already-used partition as fresh validation.
